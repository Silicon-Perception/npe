## 基础概念
### Q：NPP是什么？
A：NPP（Network Perception Protocol）是一种面向物联网场景的轻量级通信协议，专注于变化数据的增量传输。

**设计理念：**
- 传统轮询方式：定期查询所有数据，即使大部分数据未变化
- NPP 方式：仅传输变化的管道数据，静态时几乎不占用带宽

**适用场景：**
- 传感器网络（数据变化频率低）
- 低功耗广域网
- 边缘计算节点间通信

### Q：NPP有哪些技术优势？
A：NPP 的设计特点带来以下优势：

**带宽效率：**
- 数据变化少时，带宽占用显著降低
- 静态场景下几乎不占用带宽

**功耗表现：**
- 无显式心跳包，减少空闲时的功耗
- 增量传输减少数据发送量
- 核心操作采用"零计算"设计：比较和赋值，不使用乘法器、除法器、变换运算和熵编码

**连接管理：**
- 无连接状态管理，网关压力小
- 适合大规模设备接入场景

**代码实现：**
- 核心逻辑简洁，代码量较少

### Q：NPP可以替代现有协议吗？
A：NPP 适用于特定场景，不是所有场景都适合：

**适合的场景：**
- 数据变化频率低的传感器网络
- 对功耗敏感的设备
- 带宽受限的网络环境

**不适合的场景：**
- 需要实时音视频传输
- 大数据量文件传输
- 需要复杂路由的网络

## 使用相关
### Q：使用NPP需要学习很多新知识吗？
A：不需要，开发者只需要关注业务数据：
- 简单的 API 接口
- 不需要关心连接管理、重传等底层逻辑

### Q：NPP可靠性怎么样？会不会丢数据？
A：NPP 提供以下可靠性机制：
- 基于帧ID的状态检测，可发现数据丢失
- 支持应用层加密
- 具体可靠性取决于网络环境和使用方式

### Q：NPP支持哪些传输方式？
A：支持主流传输方式：
- UDP：默认传输方式
- TCP：兼容现有互联网传输

## 性能相关
### Q：NPP的功耗表现如何？
A：功耗表现取决于具体使用场景：
- 数据变化越少，带宽占用越低
- 无显式心跳包，空闲时功耗较低
- 具体功耗数据请参考测试报告（如有）

### Q：NPP的延迟怎么样？
A：NPP 的延迟特性：
- 无连接建立过程，减少握手延迟
- 延迟取决于网络环境和配置参数

### Q：NPP支持多少设备同时连接？
A：NPP 的设计特点：
- 无连接状态管理，网关压力小
- 实际设备数量受网关硬件和网络环境限制

## 迁移相关
### Q：现有的MQTT/CoAP项目怎么迁移到NPP？
A：NPP 提供类似的 API 接口：
- publish 操作对应 `npp_pipe_write`
- subscribe 操作对应 `npp_pipe_on_data` 回调

### Q：NPP可以和其他协议共存吗？
A：可以：
- 通过网关可以和其他协议对接
- 支持混合组网
